# 天使桥双账号完整演示方案

## 目标

用两个成熟 showcase 账号录制一条完整视频：展示资料、人生树、资源/心愿发布、小天整理、真实匹配、双方同意、聊天、桥约开始确认、桥约完成确认和成长值变化。

两个账号初始互不认识：没有关注、粉丝、好友消息、聊天、匹配同意记录和桥约。两边只预置完整资料与可被匹配的公开帖子，匹配和桥约必须在视频中真实产生。

| 昵称 | 设计小站 | 摄影师小林 |
| 账号池 | `showcase` | `showcase` |
| 阶段 | 壮年期·扎根积累 | 壮年期·扎根积累 |

| 兴趣标签 | 职场、科技、摄影摄像、生活记录 | 摄影摄像、职场、生活记录、科技 |

建议只预置账号资料、人生树和一条公开帖子，不预置关系或桥约。分数高于 500 是为了稳定显示成熟阶段；视频中的桥约完成后，双方真实成长值再增加 20。

## 两条真实匹配帖子

### 账号 A：我拥有

- 类型：出租物品 / 空间资源
- 标题：北京周末工作室使用权
- 我提供：北京朝阳周末工作室，周六、周日 10:00–18:00，可用于拍摄、直播或小型共创。
- 我获得：品牌摄影服务（产品图、环境图）。
- 地点：北京市 / 北京市；可线下完成，也可先线上沟通。
- 第一步行动：本周先线上确认拍摄清单和时间。
- 完成标准：交付 12 张精修产品图和 3 张环境图。
- 退出方式：如一方无法履约，提前 24 小时说明并协商调整。

### 账号 B：我拥有

- 类型：交换技能
- 标题：品牌摄影服务换拍摄空间
- 我提供：品牌产品拍摄、环境拍摄和基础后期，按清单交付成片。
- 我获得：北京拍摄空间，以及必要的设计排版支持。
- 地点：北京市 / 北京市；可先线上确认需求。
- 第一步行动：先看工作室照片并确认产品数量。
- 完成标准：完成约定拍摄并交付约定数量的精修照片。
- 退出方式：拍摄计划变化时提前沟通，不临时失联。

两条帖子必须属于两个不同账号、均处于公开匹配状态。标题和表单标签取自真实发布表单；不要用前端 `DISCOVER_CARDS` 或 `CHANNEL_ITEMS` 冒充核心匹配数据。

## 录制顺序

### 1. 开场与真实账号状态

1. 用账号 A 登录，展示首页：成长分、人生树阶段、拥有/心愿数量。
2. 进入“我”，展示昵称、简介、人生树成长卡、画像关键词和 0 关注/粉丝/搭桥。
3. 进入人生树编辑页，展示 A 的拥有与心愿标签；保存一次，返回首页确认数量和标签同步。
4. 进入消息页：小天入口保留，互动通知为 0，好友/陌生人为空，证明两个成熟账号初始也互不认识。

### 2. A 与小天整理真实意图

1. 从消息页进入小天聊天。
2. A 发送：`我有北京朝阳周末工作室，周六日可以使用，希望换品牌摄影服务。`
3. 等待小天回复，确认整理卡片中的“我提供”“我需要”“地点”与这句话一致；缺失字段显示待填写，不用静态的周末工作室/品牌照片 fixture。
4. 点击“编辑意图”，进入发布帖子页；确认自动高亮“我拥有”和“出租物品”，表单只填入对话中已有内容。
5. 补齐地点、第一步行动、完成标准、退出方式，提交并发布。
6. 发布后停留在帖子详情，展示真实标题、表单标签和正文。

### 3. A 触发真实匹配

1. 在 A 帖子发布完成后触发匹配。
2. 打开小天推荐，展示 B 的真实帖子、真实匹配度和 1–3 条后端理由。
3. A 点击“确定邀请”，确认 A 的决定变为 accepted；不要手动改前端状态。

### 4. 切换 B，完成另一半同意

1. 退出 A，登录 B。
2. 从桥约/小天推荐进入同一 `matchId` 的匹配详情，查看 A 的真实帖子。
3. B 点击接受；回到桥约确认双方状态变为 mutual accepted，并确认后端自动生成 pact。
4. 进入消息页，打开双方真实会话，发送一句：`我先确认工作室时间，再按清单完成拍摄。`
5. 如需展示 SSE，可在另一浏览器窗口保持 A 会话，观察 B 的消息实时出现。

### 5. 真实桥约开始确认

1. B 从桥约列表进入 `/bridge/schedule?matchId=...`，查看后端生成的履行安排：我提供、我获得、地点、第一步行动、完成标准、退出方式。
2. B 点击“确认开始履约”，看到 B 已确认、等待 A。
3. 切换回 A，同一 `matchId` 点击“确认开始履约”。
4. 确认状态变为进行中，桥约状态由 waiting_start 变为 active。

### 6. 真实桥约完成与成长值变化

1. 为了视频节奏，口头说明“双方已完成拍摄交付”，不需要等待现实时间。
2. A 在同一桥约点击“确认履约完成”，状态显示等待 B。
3. 切换 B 点击“确认履约完成”。
4. 后端将 pact 置为 completed，并给 A、B 各增加 20 成长值。
5. 回到双方首页/人生树，展示成长分和成长值同步增加；桥约完成数也变为真实的 1。

## 需要避开的当前静态入口

- 不点击 `/bridge/confirm` 里的“演示对方确认”；它只是旧的单页 fixture，不能作为双方真实同意证据。
- 不用发现页静态卡片证明匹配成功；匹配卡必须来自 `getMatches` 和真实 publication。
- 不把前端固定的聊天初始文案当作真实聊天记录；真实聊天需通过消息接口发送并在另一账号读取。
- 不在视频中把“互动通知 0”、静态频道内容、灵宠装扮和协议页说成后端业务闭环；这些只作为外围界面展示。

## 录制前一次性准备

1. 确认 A/B 资料完整、账号池均为 showcase、成长值处于成熟阶段。
2. 清理 A/B 之间已有的 publication match、consent、conversation、pact，保留两条公开帖子或按第 2 节现场创建。
3. 清理浏览器两个账号的 localStorage，分别使用两个独立浏览器窗口，避免 token 串号。
4. 先用测试窗口完整走一遍：A 接受 → B 接受 → B 开始确认 → A 开始确认 → A 完成确认 → B 完成确认。
5. 录制时只保留一条匹配；不要同时创建第二条相同意图帖子，避免推荐列表出现多个相似结果。

## 成功标准

- A/B 初始互不认识，关系数据为空。
- A/B 帖子和资料来自后端 showcase 数据，不依赖前端静态卡片。
- 匹配度、匹配理由、双方 consent、conversation、pact 状态均可由 API 读取。
- 双方各自确认开始和完成后，pact 为 completed，双方成长值各增加 20。
- 首页、人生树、桥约列表在刷新后仍显示完成结果。
- 所有静态 fixture 页面均明确作为外围演示，不冒充核心真实数据。

本方案只定义演示数据和录制路径，尚未写入新的 A/B 资料、帖子或关系数据。

## 录制前测试与一键回滚

生产容器内执行 `npm run demo:reset-showcase` 会只处理账号 A/B 的 showcase 数据：恢复完整资料、成长值、人生树和两条互补公开帖子，同时清理 A/B 参与的匹配、同意、聊天、小天记录和桥约。真实用户的 `live` 池不受影响。

推荐顺序：

1. 先执行一次重置，分别登录 A/B，完整走通真实匹配、聊天、开始确认、完成确认。
2. 确认双方成长值各增加 20、桥约进入已完成。
3. 正式录屏前再次执行同一重置命令。
4. 清理两个浏览器窗口的本地存储并重新登录；此时 A/B 重新处于互不认识状态，但成熟外围 fixture 和两条初始公开帖子仍保留。

脚本位置：`scripts/reset-showcase-demo.ts`。它可以重复执行，因此测试和正式录制使用完全相同的初始数据。
