## 6. 当前两个 Bug 的处理顺序

### P0-A：导航页面 `request validation failed`

用户现象：

- 登录后点击底部“消息”“桥约”“我”，出现 1–3 个错误 Toast；页面仍部分正常显示。
- 公网接口 `/api/conversations`、`/api/pacts`、`/api/matches`、`/api/dashboard`、`/api/life-tree` 会共同失败。

已确认根因：

```text
matches.<old-match-id>.proof.matchReasons
Too small: expected array to have >=1 items
```

说明：数据库里已有旧匹配快照没有 `matchReasons`，而当前 `MatchProofSchema`/相关 ViewModel 要求至少一条。不要改前端 Toast 文案来掩盖问题。

最小修复方向：

- 在读取旧状态的单一边界，将历史空 `matchReasons` 补成可展示的已有理由（优先使用 `valueToYou` / `valueToOther` / `executionFit` 中已有文本），再交给当前 schema；或在当前明确的持久化恢复处做一次最小兼容归一化。
- 不要删除数据库匹配，不要重做匹配算法，不要改变前端页面。
- 修复后部署后端，直接交给用户点击消息、桥约、我验证。

相关代码：

- `src/pool/match-pool-service.ts`：`ensureLoaded()`、`toMatchView()`
- `src/domain/contracts.ts`：`MatchProofSchema`
- `src/pool/contracts.ts`：`MatchPoolStateSchema`、`PoolMatchSchema`
- `src/http/api.ts`：统一错误解包

### P0-B：认证成功后回到欢迎/首页

用户现象：

- 虚拟手机号和真实手机号均可能在点击“验证并登录”后回到欢迎页或首页，看起来没有进入稳定的应用状态。
- 真实新用户登录后应进入资料补充引导；已有完整资料账号应直接进入首页。

关键代码：

- `frontend-final/src/components/auth/AuthFlow.tsx`
- `frontend-final/src/components/auth/AuthGate.tsx`
- `frontend-final/src/lib/angelbridge-api.ts`
- `frontend-final/src/lib/angelbridge-session.ts`
- `frontend-final/src/app/page.tsx`

当前期望状态机：

```text
无 token                      → 登录界面
短信 login 返回完整资料         → 首页
短信 login 返回 demographicsIncomplete → 资料引导
短信 register 返回             → 昵称/资料引导
资料保存成功                   → 首页
```

修复原则：

- 只修会话保存、认证结果回调或引导状态判断中实际导致回跳的最小点。
- 不改变登录页视觉、不改手机号和验证码规则、不新增密码登录。
- 用户已要求修复后由其本人验证，不需要 Codex 再调用业务登录接口。
