# 天使桥｜灵宠语音接口与联调说明

> 当前状态：纯 TypeScript 语音领域闭环和豆包适配器已经实现；Next.js 尚未初始化，因此 HTTP Route Handler 由 R1、R2 冻结 Web 目录后接入。真实豆包调用需要控制台凭证和音色 ID。

## 1. MVP 语音链路

```text
R2 浏览器 MediaRecorder
→ POST /api/voice/turn
→ 豆包录音文件极速版 ASR
→ 方舟 Doubao Seed Function Calling
→ ParseResultSchema 校验
→ Seed-TTS 2.0
→ transcript + replyText + ParseResult + audio
```

第一版采用点击开始/结束录音，不实现全双工打断。建议前端限制单次录音 15 秒，后端领域契约限制音频不超过 10 MB。

## 2. HTTP 接口契约

### `POST /api/voice/turn`

请求使用 `multipart/form-data`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `sessionId` | string | 当前演示 Session |
| `personaId` | string | 当前用户 |
| `audio` | File | 浏览器录音，建议 `audio/webm` |

Route Handler 将 `File` 转成 `Uint8Array`，调用 `VoiceTurnService.process()`。响应为：

```json
{
  "turnId": "turn_xxx",
  "sessionId": "session_xxx",
  "personaId": "persona_xxx",
  "mode": "fixture",
  "transcript": "我需要在杭州找一间房。",
  "replyText": "主人，我听到你想在杭州找一间房，要保存这项需求吗？",
  "parseResult": {},
  "audio": {
    "contentType": "audio/wav",
    "base64": "..."
  },
  "createdAt": "2026-08-26T13:00:00.000Z"
}
```

前端将 Base64 转为 `Blob` 后播放。P0 回复不超过两句话，因此先以内嵌音频换取单接口联调效率；后续再改对象存储 URL。

## 3. 两种运行模式

| 模式 | 行为 |
|---|---|
| `fixture` | 固定转写、固定 ParseResult、可播放的静音 WAV；用于 R2/R3 不等待凭证完成交互 |
| `live_ai` | 真实调用豆包 ASR、方舟和 TTS；任何环节失败直接返回错误，不静默切换 Fixture |

`ParseResult.source` 与 `isSynthetic` 必须一致。真实语音允许只产生 Offer、Need 或 Goal 中的一类节点，不再要求用户一句话同时表达供给和需求。

## 4. 前端交互状态

```text
idle → recording → uploading → understanding
→ confirming → speaking → completed
```

- `recording`：显示计时和结束按钮；
- `uploading/understanding`：灵宠进入倾听、思考状态；
- `confirming`：同时展示转写文字和 Value Node，用户确认后才保存；
- `speaking`：播放返回音频，允许停止和重播；
- 请求失败：明确显示真实 AI 失败，不展示预置结果冒充成功。

## 5. 环境变量

```dotenv
VOICE_MODE=live_ai
DOUBAO_ARK_API_KEY=
DOUBAO_ARK_MODEL=doubao-seed-2-0-lite-260215
DOUBAO_SPEECH_API_KEY=
DOUBAO_ASR_RESOURCE_ID=volc.bigasr.auc_turbo
DOUBAO_TTS_RESOURCE_ID=seed-tts-2.0
DOUBAO_TTS_SPEAKER=
DOUBAO_TTS_STYLE=请用温柔、轻快、有陪伴感的语气说话。
```

使用新版豆包语音控制台的 API Key 路径。所有密钥仅放服务端环境变量，不传给浏览器。

## 6. R1、R2、R3 联调边界

| 角色 | 独立工作 | 联合确认 |
|---|---|---|
| R1 后端/AI | VoiceTurnService、豆包 Provider、Schema、错误响应 | 与 R2 冻结 multipart 请求；与 R3 确认回复文案长度和确认节点 |
| R2 前端 | MediaRecorder、录音上传、Base64 音频播放、接口状态 | 用 Fixture 接口完成页面，再切换 `live_ai` |
| R3 UI/UX | 七个交互状态、麦克风权限提示、转写和节点确认界面 | 验收灵宠反馈是否可感知、可停止、可重播 |

## 7. 拿到凭证后的冒烟顺序

1. 单独调用极速 ASR，确认返回 `result.text`；
2. 单独调用方舟，确认强制返回 `record_value_nodes` 工具参数；
3. 单独调用 TTS，确认所选 Speaker 属于 Seed-TTS 2.0；
4. 设置 `VOICE_MODE=live_ai` 跑一次完整 `VoiceTurnService`；
5. 再接 `/api/voice/turn`，最后与浏览器录音联调。

当前没有凭证时，适配器的请求与响应转换由 Mock 测试覆盖，但不能宣称真实云服务已经联通。
