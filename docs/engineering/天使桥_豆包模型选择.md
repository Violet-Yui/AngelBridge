# 天使桥：豆包模型选择

> 适用阶段：72 小时黑客松开发期  
> 目标：用尽量少的模型完成资源与心愿理解、AI 辅助匹配、灵宠文字回复与可选语音交互。

## 1. 选型结论

第一版只接入一个大语言模型：

- 服务：火山方舟在线推理
- 模型：Doubao-Seed-2.0-lite
- 模型 ID：`doubao-seed-2-0-lite-260215`
- API Base URL：`https://ark.cn-beijing.volces.com/api/v3`

该语言模型统一承担：

- 将用户自然语言整理成资源、心愿、约束和边界。
- 对确定性匹配结果进行语义辅助评分。
- 生成可解释的匹配理由、未知项与下一步建议。
- 生成灵宠“小天”的文字回复。

第一版不接入第二个 LLM，也不做多模型路由。

## 2. 选择 Doubao-Seed-2.0-lite 的原因

- 一个模型即可覆盖当前文本能力，减少接入和调试成本。
- 支持中文理解、结构化输出和工具调用，适合现有资源卡片与匹配评估结构。
- Lite 版本兼顾响应速度、调用成本和现场演示稳定性。
- 当前仓库已经按火山方舟兼容接口实现 Provider，继续使用该模型改动最少。
- 本项目不需要 Pro 模型面向复杂长链路 Agent 的额外能力。

官方参考：

- [火山方舟模型调用示例](https://www.volcengine.com/docs/82379/1795150)
- [火山方舟工具调用](https://www.volcengine.com/docs/82379/1958524?lang=zh)

## 3. AI 在匹配中的职责边界

AI 不单独决定最终匹配度。最终匹配继续采用“确定性规则为骨架、AI 提供语义增量”的方式：

```text
基础分数 = 资源与需求互补 + 硬约束 + 时间地点 + 交换方式
AI 增量 = 语义契合度 + 可解释理由 + 风险与未知项
最终结果 = 受范围限制的 AI 增量 + 确定性基础分数
```

这样既能体现 AI 原生能力，也能保证同一组演示数据的结果稳定、可解释、可复现。

## 4. 语言模型与语音模型的关系

语言模型和语音模型不是同一个模型。完整语音链路由三个独立能力组成：

```text
用户语音
  → ASR：volc.bigasr.auc_turbo
  → 用户文字
  → LLM：doubao-seed-2-0-lite-260215
  → 灵宠回复文字
  → TTS：seed-tts-2.0
  → 灵宠回复音频
```

| 能力 | 服务或资源 ID | 用途 |
| --- | --- | --- |
| 语音识别 ASR | `volc.bigasr.auc_turbo` | 将浏览器录音转换成中文文本 |
| 语言模型 LLM | `doubao-seed-2-0-lite-260215` | 理解用户表达并生成结构化结果或回复 |
| 语音合成 TTS | `seed-tts-2.0` | 将灵宠文字回复合成为 MP3 |
| 推荐音色 | `zh_female_vv_uranus_bigtts` | Vivi 2.0，作为轻快、有陪伴感的灵宠声音 |

官方参考：

- [录音文件极速版识别 API](https://www.volcengine.com/docs/6561/1631584?lang=zh)
- [豆包语音音色与产品动态](https://www.volcengine.com/docs/6561/162929?lang=en)

## 5. 黑客松接入顺序

为减少同时联调多个外部服务的风险，按以下顺序接入：

1. 接入 `doubao-seed-2-0-lite-260215`，先完成文字理解、匹配辅助和灵宠文字回复。
2. 接入 ASR，让用户可以用语音输入。
3. 接入 TTS 和 Vivi 2.0，让灵宠用语音回复。

AI API 暂时不可用时，可以使用明确标记的 Fixture；不得将 Fixture 表述为真实 AI 结果。

## 6. 当前模型接入准备状态

### 已具备

- 已有火山方舟匹配 Provider。
- 已有豆包 ASR、语言模型、TTS Provider 和语音编排服务。
- 已有 Provider 单元测试。
- `.env.example` 已定义模型与语音服务所需环境变量。

### 尚未完成

- 当前环境没有真实 API Key，也没有生产 `.env`。
- 匹配 HTTP 主流程仍使用 `rule` / `fixture_ai`，现有 `live_ai` Provider 尚未接入应用服务。
- 语音 HTTP 接口仍是 Fixture 输入，尚未调用真实语音编排服务。
- 前端仍提交模拟转写文本，并使用浏览器 `speechSynthesis` 播放，不是播放 TTS 返回的音频。
- 尚未对真实方舟、ASR、TTS 服务分别执行最小 Smoke Test。
- 推荐音色尚未写入生产环境变量。

因此当前状态是：模型 Provider 已实现，真实业务链路尚未接通。不能只填写 API Key 就宣称模型接入完成。

## 7. 环境变量目标

语言模型：

```dotenv
AI_MODE=live_ai
AI_BASE_URL=https://ark.cn-beijing.volces.com/api/v3/chat/completions
AI_API_KEY=<server-only-secret>
AI_MODEL=doubao-seed-2-0-lite-260215
```

语音能力：

```dotenv
VOICE_MODE=live_ai
DOUBAO_ARK_API_KEY=<server-only-secret>
DOUBAO_ARK_MODEL=doubao-seed-2-0-lite-260215
DOUBAO_SPEECH_API_KEY=<server-only-secret>
DOUBAO_ASR_RESOURCE_ID=volc.bigasr.auc_turbo
DOUBAO_TTS_RESOURCE_ID=seed-tts-2.0
DOUBAO_TTS_SPEAKER=zh_female_vv_uranus_bigtts
DOUBAO_TTS_STYLE=请用温柔、轻快、有陪伴感的语气说话。
```

API Key 仅写入服务器环境变量或未入库的 `.env`，不得写入前端构建变量、Git 仓库或文档示例值。

## 8. 最终决策

- 第一版语言模型确定为 `doubao-seed-2-0-lite-260215`。
- 第一版不接入第二个 LLM，不实现多模型路由。
- ASR 与 TTS 是独立语音服务，不属于语言模型。
- 先接语言模型，再按演示时间决定是否加入 ASR 和 TTS。
