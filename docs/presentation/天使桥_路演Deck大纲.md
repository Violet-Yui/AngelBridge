## 0. Deck 的沟通任务

### 我们希望评委最终相信什么

> **天使桥不是把多个平台功能装进一个 App，而是用个人 AI Agent 和统一价值模型，重构人、物、能力、机会与愿望彼此发现和协商的入口；团队已经将这个宏大愿景收束成一条能在黑客松现场运行和验证的最小闭环。**

### 评委需要依次形成的五个判断

1. 这确实是一个普遍、真实且高成本的问题；
2. 团队对问题的洞察不同于“再做一个资源平台”；
3. AI 在产品里不是聊天壳，而是新的交互与协作主体；
4. 96 小时交付范围清楚，并能证明底层机制而不是堆功能；
5. 如果底层机制成立，产品具有从小范围验证走向广义价值网络的潜力。

### Deck 全程必须守住的事实边界

- 长期愿景可以覆盖物品、空间、技能、工作、关系、信息和成长；
- 本次只承诺实现“表达—匹配—双方确认—桥约—结果写回”的统一闭环；
- 三个场景用于证明同一引擎的通用性，不等于同时上线三个完整垂直平台；
- 房产交易、真实招聘履约、婚恋上线、支付担保和全网持续监控不属于本次交付；
- 演示数据、测试目标和真实成果必须明确区分；
- 没有发生的数据不能包装成用户增长、成桥率或商业成绩。

## 第 2 页｜问题：社会不缺资源，缺的是让供需彼此看见的共同语言

### 这一页的任务

证明问题真实而且不仅是“搜索不方便”。

### 建议标题

**社会不缺资源，缺的是让供需彼此看见的共同语言**

### 屏幕核心文案

- 物品、房屋、技能、职位、伙伴和信息分散在不同平台；
- 用户必须反复描述自己，再亲自搜索、筛选、私聊和协调；
- 有价值的供需能否相遇，常常取决于曝光、投流和熟人关系；
- 真实需要不断变化，静态资料和一次搜索很快失效。

### 建议视觉

左侧是一个完整的人，右侧散落多个垂直平台入口；同一个人的资源与愿望被拆碎，彼此之间没有连接。

### 不要这样讲

不要罗列“找人难、找物难、找资源难”后直接跳到解决方案。必须指出共同根因：**个人价值和人生意图没有统一、实时、受本人控制的表达方式。**

### 评委听完后的判断

“问题不是平台数量不足，而是跨平台、动态、双向的意图无法被理解。”

## 第 3 页｜洞察：流量平台理解你想看什么，却不理解你的人生缺什么

### 这一页的任务

建立天使桥与小红书、抖音、淘宝、招聘和社交平台之间最核心的认知差异。

### 建议标题

**流量平台理解你想看什么，却不理解你的人生此刻缺什么**

### 屏幕对比

| 流量逻辑 | 天使桥的价值逻辑 |
|---|---|
| 预测你会停留在哪条内容 | 理解你希望实现什么现实结果 |
| 让用户不断浏览和搜索 | 让 Agent 持续寻找与筛选 |
| 优化点击、互动和曝光 | 优化双向价值与真实行动 |
| 平台替用户决定推荐 | 用户控制意图、边界和披露 |

### 核心金句

> **我们不是给资源再建一个流量池，而是给每个人一个真正代表自己的 Agent。**

### 建议视觉

中间做一道清晰分界：左侧是信息流漏斗，右侧是“愿望—Agent—现实连接”的路径。

### 评委听完后的判断

“团队不是在做更精准的内容推荐，而是在改变用户与资源网络的交互方式。”

## 第 4 页｜产品：把一生的拥有与需要，交给一个站在你这边的小天

### 这一页的任务

用一句话讲清产品是什么，以及长期愿景如何被统一。

### 建议标题

**把一生的拥有与需要，交给一个站在你这边的小天**

### 一句话产品定义

> **天使桥帮助每一个拥有人生资源、能力、愿望和成长课题的人，让专属 AI 伙伴“小天”持续理解“我拥有什么、我需要什么、愿意如何交换”，主动发现并协商可信、双向有益的连接。**

### 产品公式

**人生价值图谱 × 个人 AI 伙伴 × Agent-to-Agent 价值网络 × 现实成长游戏**

### 屏幕辅助说明

- 用户不需要学习新的分类体系，只需向小天表达；
- 小天将表达转成由用户确认和控制的价值节点与意图；
- 不同人的小天先沟通，值得连接时再询问主人。

### 建议视觉

以“小天”为中心，连接生命树、其他 Agent 和现实行动，避免做成一排功能图标。

### 评委听完后的判断

“产品入口是个人 Agent，底层对象是价值与意图，不是一堆频道。”

## 第 5 页｜产品体验：一树、一灵、一桥、一约、一程

### 这一页的任务

让抽象的平台概念变成容易记忆的完整产品体验。

### 建议标题

**天使桥把人生价值网络，变成五个可以感知的产品对象**

### 屏幕内容

1. **一棵生命树**：看见自己的资源、能力、愿望与成长；
2. **一个小天**：理解、整理、发现、协商和提醒；
3. **一座桥**：解释双方为什么值得相遇；
4. **一份桥约**：明确双方提供什么、获得什么、下一步做什么；
5. **一段旅程**：真实行动反哺生命树，推动人生升级。

### 模拟人生映射

资源是背包，能力是技能树，愿望是任务栏，连接是队友，行动结果是成长经验。

### 关键边界

成长只与用户过去的自己比较；不建立公开的人生价值排行榜，也不把财富、健康或充值金额当成人的综合价值。

### 建议视觉

用一条连续路径串联五个对象，重点突出“桥约”和“现实结果”，避免五张互不关联的功能卡。

### 评委听完后的判断

“品牌叙事、核心功能和持续使用机制是同一套逻辑。”

## 第 6 页｜工作方式：从一句愿望，到一段可以开始的现实行动

### 这一页的任务

展示端到端闭环，证明产品不止停留在匹配结果。

### 建议标题

**从一句愿望，到一段可以开始的现实行动**

### 五步闭环

1. **表达**：用户说出“我有什么、我需要什么、愿意怎样交换”；
2. **理解**：小天提取 Value Node 与 Intent，用户确认边界；
3. **发现**：系统进行双向召回、硬条件过滤和证据判断；
4. **协商**：两个小天交换最小必要信息，分别向主人建议搭桥；
5. **行动**：双方确认桥约，结果写回生命树。

### 核心对象

```text
Value Node：物品 / 空间 / 能力 / 机会 / 关系意图 / 信息 / 成长目标

Intent：提供什么 + 需要什么 + 交换方式 + 约束 + 边界 + 时效
```

### 建议视觉

一条从用户 A 到用户 B 的连续流程；连接线先于节点出现，突出两个 Agent 之间的协商与两端用户确认。

### 评委听完后的判断

“这是一条可开发、可演示、可记录状态的真实产品链路。”

## 第 7 页｜AI 原生性：AI 不只负责理解，还代表用户发现与协商

### 这一页的任务

回答评委最可能提出的问题：“为什么一定需要 AI，这是否只是大模型套壳？”

### 建议标题

**AI 不只负责理解，还代表用户持续发现与协商**

### AI 负责的工作

- 从自然语言、图片和链接中提议价值节点；
- 理解跨类别表达，例如“空间换服务”“技能换机会”；
- 找出真正影响匹配的缺失信息；
- 让不同用户的小天在授权范围内澄清条件；
- 生成有证据、有未知项的 Match Proof；
- 将连接转成可执行的桥约和成长复盘。

### 确定性系统负责的工作

- 数据结构、权限和状态；
- 时间、地点、资格和可见范围等硬约束；
- 双向效用计算与结果排序；
- 高风险动作的人类确认；
- 事实证据和模型输出校验。

### 核心表达

> **AI 负责理解复杂人生，代码负责守住事实与边界。**

### 技术前瞻

内部先实现个人 Agent 之间的能力发现、任务状态和结构化协商；长期兼容 A2A 与 MCP 等开放协议。

### 评委听完后的判断

“AI 改变了输入、匹配和协作流程，同时关键逻辑仍然稳定可控。”

## 第 8 页｜差异化：我们不和某一个垂类抢入口，而是重构所有垂类共同的上游

### 这一页的任务

说明竞品边界与创新点，避免被理解为综合分类信息平台。

### 建议标题

**我们不和某一个垂类抢入口，而是重构它们共同的上游**

### 建议对比表

| 产品类型 | 核心对象 | 优化目标 | 天使桥的不同 |
|---|---|---|---|
| 内容平台 | 内容 | 停留与传播 | 从“想看什么”转向“想实现什么” |
| 交易平台 | 商品 | 成交与 GMV | 支持能力、时间、空间和非货币交换 |
| 招聘平台 | 岗位与简历 | 招聘转化 | 同时理解项目、能力、投入、回报和长期目标 |
| 社交平台 | 人的资料 | 连接与活跃 | 双向意图、渐进披露和现实行动 |
| 通用 AI | 对话与外部信息 | 完成单次任务 | 持续维护个人价值图谱，并连接另一端的实时意图 |

### 四个创新支点

**统一价值模型、个人 Agent、双向协商、结果反哺成长。**

### 评委听完后的判断

“天使桥的创新不是把几个行业放在一起，而是提出了一个跨行业成立的新底层对象和交互方式。”

## 第 9 页｜黑客松范围：愿景可以很大，96 小时只证明一个底层命题

### 这一页的任务

这是整套 Deck 最重要的范围控制页。主动回答评委对“大而全、做不完”的担忧。

### 建议标题

**愿景可以很大，96 小时只证明一个底层命题**

### 本次要证明的命题

> **同一个 AI 原生价值模型，能否把不同类型的人生资源与愿望转成结构化 Intent，并促成可解释、双向同意、可以行动的连接？**

### 本次必须完成

- 自然语言创建并确认 Value Node；
- 激活一个 Offer 与一个 Need；
- 双向向量召回与硬约束过滤；
- Match Proof；
- 两端用户分别确认；
- 生成桥约与第一次行动；
- 结果写回生命树。

### 本次明确不做

- 真实房产交易、支付、押金与担保；
- 真实招聘合同、投资与股权撮合；
- 婚恋上线或自动向真人发送私信；
- 全网长期抓取和完整新闻平台；
- 统一人生价值分与付费排名；
- 多个不可控的自治 Agent 集群。

### 范围表达原则

这页必须进入核心 Deck，不能只放在答辩附录。主动承认边界会提高完成度可信度，而不是削弱愿景。

### 评委听完后的判断

“团队知道自己在 96 小时内要交付什么，也知道哪些暂时不能承诺。”

## 第 10 页｜Demo：同一套引擎，连接三种完全不同的价值

### 这一页的任务

把通用能力变成现场可见、可复现的产品证明。

### 建议标题

**同一套引擎，连接三种完全不同的价值**

### 主 Demo：空间换服务

**用户 A：** 周末有闲置工作室，需要一组品牌照片。  
**用户 B：** 需要两天拍摄场地，可以提供品牌摄影。

小天完成：

1. 将双方自然语言转为 Value Node 与 Intent；
2. 识别“空间使用权”和“摄影服务”可以互换；
3. 展示双方收益、时间条件、证据和未知项；
4. 两端分别确认；
5. 生成桥约：“两天场地使用权换一组品牌照片”。

### 两个快速证明案例

- **能力 × 机会：** 产品运营能力寻找技术伙伴，开发者寻找有真实用户的项目；
- **志趣 × 成长：** 摄影教学与英语陪练形成四周技能互助。

### 演示顺序

主案例实时输入并完整跑通；另外两个案例只快速切换结果，证明共享同一 Schema、API、匹配引擎与桥约组件。

### 不应展示

不要在三分钟里分别演示房源、招聘、婚恋、新闻和成长五套页面，这会立即被评委判断为功能堆砌。

### 评委听完后的判断

“团队用一个完整案例证明闭环，再用两个案例证明底层通用性。”

## 第 12 页｜未来：让每个人都拥有自己的价值网络入口

### 这一页的任务

把长期愿景与已经证明的底层机制连接起来，并完成情绪收束。

### 建议标题

**让每个人都拥有自己的价值网络入口**

### 三阶段路径

1. **一个社区：** 在创作者、共居或高校社区验证多类型价值互助；
2. **连接垂直服务：** 接入房源、招聘、日历、地图、服务和内容工具，专业平台继续负责履约；
3. **开放 Agent 网络：** 让个人、组织和商家的 Agent 以统一意图与桥约协议相互发现和协商。

### 商业方向一句话

个人为 Agent 的持续监测、自动化与深度服务付费；组织为认证、私域价值网络和匿名化洞察付费。付费不改变自然匹配结果。

### 最终收束文案

> 世界上不缺资源，也不缺愿望；缺的是一种让每个人都能被真正理解、让每份价值都能找到去处的共同语言。

> **天使桥——让每一份价值，遇见真正需要它的人。**

### 建议视觉

从一个人的生命树扩展到社区，再连接成社会价值网络；最后回到产品 Logo 与 Slogan。不要以普通“谢谢”页结束。

### 评委听完后的判断

“今天的 Demo 是一个小闭环，但它确实通向一个更大的产品。”

# 评委问答附录

## 附录 A｜统一价值模型

### 回答的问题

“物品、房屋、工作、关系和信息差异这么大，凭什么说是同一个产品？”

### 建议内容

展示统一的 `Value Node` 与 `Intent` Schema：

- `value_type`：价值类型；
- `offer / need`：提供与需要；
- `outcome`：希望发生的现实结果；
- `exchange_modes`：金钱、物物、时间、能力、合作、赠予；
- `constraints`：时间、地点、预算和资格；
- `boundaries`：不可接受条件和隐私边界；
- `evidence`：身份、产权、作品或经历；
- `visibility`：Agent 可用、匿名匹配、指定对象或公开；
- `freshness`：生效、暂停、完成或过期；
- `risk_level`：普通、需认证或高风险确认。

共同 Schema 负责表达与发现，不同领域继续拥有独立认证、排序和履约规则。

---

## 附录 B｜匹配算法与 Agent 协商

### 回答的问题

“匹配是否只是让大模型看两段文字打分？”

### 建议内容

```text
MatchScore = HardGate × ReciprocalUtility × TrustConfidence × Freshness

ReciprocalUtility = harmonic_mean(ValueToA, ValueToB)
```

- SQL / 规则处理时间、地点、资格、可见范围等硬约束；
- pgvector 分别进行 Need → Offer 与 Offer → Need 双向召回；
- 调和平均压低单边有利的匹配；
- LLM 负责跨类别理解、澄清问题和解释；
- 解释只能引用结构化字段和证据；
- 两个 Agent 只交换被主人允许的最小必要信息。

---

## 附录 C｜信任、隐私与“人不是商品”

### 回答的问题

“如此多个人信息放在一起，如何避免滥用和歧视？”

### 建议内容

- 人本身不是资源；可被匹配的是本人授权的时间、能力、服务、合作和关系意图；
- 完整生命树默认私密，公开主页只是用户主动选择的投影；
- 身份、房源、企业、作品和关系状态按领域分别认证；
- 不允许跨领域使用敏感信息，例如婚姻信息不进入招聘排序；
- 联系方式和高敏信息在双方确认后渐进披露；
- 工作、房屋、资金和关系等高风险领域必须由人确认；
- 不建立统一人生价值分或公开排名；
- 付费购买 Agent 服务额度，不购买对其他人的排序优势。

## 附录 D｜商业模式

### 回答的问题

“如何商业化，又如何避免重新变成流量平台？”

### 建议内容

| 用户 | 付费内容 | 不出售的东西 |
|---|---|---|
| 个人 Pro | 更多活跃愿望、更高扫描频率、外部连接、自动化和复盘 | 自然匹配排名 |
| 商家 / 组织 | 认证、批量机会、Agent 接待、私域网络与匿名化洞察 | 用户完整生命树 |
| 成交服务 | 在适合的低风险服务或交易中收取技术服务费 | 绕过双方同意的触达 |

商业推广如存在必须明确标识，并与自然匹配结果分离。

# Deck 写作与制作规则

## 每页文案规则

- 每页只承担一个判断；
- 标题直接说结论，不写“市场痛点”“产品介绍”等栏目名；
- 屏幕文字只保留演讲中必须被看见的内容；
- 一句话能说清时不写四个 bullet；
- 同一个概念只完整解释一次；
- 未来能力统一使用“长期”“下一阶段”“计划”，不写成现在已经支持；
- 目标数据写“目标”，真实数据写样本、时间和口径；
- 不展示未经校准的“98% 匹配度”。

## 视觉规则

- 气质应是温暖、人本、未来感，而不是金融交易终端；
- 生命树、桥和小天是三个主要视觉母题；
- 生命树表达个人价值与成长，桥表达双向关系，小天表达用户代理权；
- 避免满屏 App 卡片、标签、积分和密集 Dashboard；
- 技术图只保留关键数据流、确认点与系统边界；
- Demo 页面视觉优先于概念插画；
- 最后阶段必须用实际产品截图替换示意 UI。

## 讲述规则

- 不说“我们要做一个什么都有的平台”；
- 说“多个场景共享一个价值意图模型和一条成桥闭环”；
- 不说“AI 自动替你做所有决定”；
- 说“Agent 负责理解、发现和草拟，人确认关键决定”；
- 不把人描述为可交易资源；
- 不把充值、健康、财富或社会身份包装成人的价值排序；
- 先展示已经做成的闭环，再讲长期协议和生态；
- 如果现场结果不及目标，展示真实数据和学到的约束，不虚构成绩。
