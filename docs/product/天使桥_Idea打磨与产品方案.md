## 0. 核心结论

### 一句话 Idea

> **天使桥帮助拥有资源、能力或愿望的人，在生活、工作、关系与成长中，由个人 AI“小天”理解双方能提供什么、需要什么、愿意怎样交换，促成可信、双向有益且可以行动的价值置换、资源交换与现实连接。**

### Slogan

> **让每一份价值，遇见真正需要它的人。**

### 品牌主张

> **天使桥——做彼此的天使。**

### 产品公式

> **天使桥 = 人生价值图谱 × 个人 AI“小天” × Agent-to-Agent 价值连接 × 现实成长闭环**

### 最重要的产品判断

天使桥不是把淘宝、招聘、内容社区、婚恋和新闻功能装进一个 App。它要重构的是这些平台共同的上游环节：

> **把一个人分散、模糊、不断变化的“拥有、需要、边界与愿望”变成可由 AI 理解的个人价值图谱，再让不同人的 Agent 在授权范围内发现并促成价值置换、资源交换与双向连接。**

物品、空间、技能、工作、合作、志趣和信息只是同一机制在不同场景中的表现。

## 1. 问题与机会

### 1.1 资源很多，但彼此难以抵达

现实中的物品、空间、能力、机会和善意散落在不同平台与私人关系中。用户必须反复搜索、比较、私聊和解释，仍然可能找不到真正合适的对象。

### 1.2 人生意图很难被传统分类表达

“用周末工作室交换品牌摄影”“寻找价值观一致的技术伙伴”“用摄影教学换英语陪练”都同时包含 Offer、Need、交换方式、时间、地点、边界和目标，无法被一个关键词或标准商品卡准确描述。

### 1.3 现有发现机制依赖流量和关系

资源更容易流向会经营流量、已有关系或能够购买曝光的人，而不一定流向最需要、最适合的人。用户也被迫花时间刷内容、维护人设和重复搜索。

### 1.4 大多数推荐只优化一方

传统搜索通常只问“这个结果是否符合发起者的需要”，却不回答另一方为何愿意参与。于是用户得到的是候选，不是双方都愿意开始的连接。

### 1.5 金钱不是唯一交换方式

现实中还存在物物交换、空间共享、技能互助、时间交换、联合创作、资源引荐和无偿帮助，但现有平台大多围绕“标价—支付”组织。

### 核心问题

> **个体的资源、能力、需要、边界和愿望缺少统一、持续且由本人控制的表达方式，导致价值置换与资源连接仍主要依靠流量曝光、垂直搜索和熟人关系。**

## 2. 产品定位与核心语言

### 2.1 什么是“人生价值置换与资源连接系统”

天使桥不替代房产、招聘、交易或社交等专业服务，而是为分散的人、资源、能力和愿望提供共同的表达、发现、协商与反馈机制：

1. **表达：** 把“我拥有什么、需要什么”变成可确认的结构；
2. **发现：** 寻找能形成双向价值的对象；
3. **协商：** 由双方小天澄清条件并准备提案；
4. **行动：** 将连接转成桥约与第一步；
5. **成长：** 把现实结果写回个人价值图谱。

### 2.2 三个核心词

- **价值置换：** 双方以各自认可的方式提供和获得价值，回报可以是金钱、物品、空间、能力、时间、机会、成果或善意；
- **资源交换：** 物品、空间、技能、服务、时间和信息发生转让、共享、互换或协作；
- **连接：** 合适的人与资源彼此抵达，并由双方决定是否交换、合作或建立关系。

关系、友谊和人生伙伴不被描述为可交易资源。这类场景强调双向理解、自主选择和建立连接；“价值置换”主要用于双方明确提供与获得内容的资源、能力和合作场景。

### 2.3 用户

长期愿景面向每一个人，首批用户应优先选择资源种类丰富、需求变化快、愿意尝试 AI 且能在小范围内形成交换的人群：

- 青年创业者、自由职业者和创作者；
- 共居社区、创业社区和高校社群成员；
- 同时拥有项目、空间、技能和成长需求的人；
- 不愿经营流量，但愿意清楚表达自己能给什么、需要什么的人。

### 2.4 天使桥不是什么

- 不是多个垂直平台首页的拼盘；
- 不是公开全部个人信息的资源黄页；
- 不是给人统一定价或排名的系统；
- 不是付费即可获得婚恋、工作或公共资源优先权的平台；
- 不是只会聊天、不能推动行动的 AI 宠物；
- 不是以浏览时长、点赞和热度为目标的内容社区。

## 3. 统一价值模型

### 3.1 Value Node：人生价值节点

天使桥不先按行业建频道，而先把个人拥有、提供、需要和追求的内容表示为统一节点。

| 节点类型 | 示例 | 关键字段 |
|---|---|---|
| 物品与资产 | 相机、设备、车辆、产品 | 所有权/使用权、状态、地点、交换方式 |
| 空间 | 房间、工作室、活动场地 | 时间、用途、容量、位置、规则 |
| 能力与服务 | 开发、设计、摄影、咨询 | 能解决的任务、产出、时间、证据 |
| 机会与组织 | 岗位、项目、合作、活动 | 角色、投入、回报、阶段、期限 |
| 关系意图 | 兴趣同伴、合作伙伴、人生伙伴 | 目标、价值观、边界、双方意愿 |
| 信息需要 | 行业动态、政策、价格和机会 | 主题、来源、阈值、频率 |
| 成长目标 | 学习、健康、创作、人生计划 | 当前状态、目标、周期、行动 |

节点默认属于用户自己，只有用户确认的内容才能进入匹配与披露。

### 3.2 Intent：一次可执行的意图

```text
Intent = Offer + Need + Exchange + Constraints + Boundary + Time
```

- `Offer`：我能提供什么；
- `Need`：我希望获得什么；
- `Exchange`：金钱、互换、合作、赠予等方式；
- `Constraints`：时间、地点、预算、资格和产出；
- `Boundary`：哪些信息可用于匹配、何时披露；
- `Time`：生效时间和期限。

房屋、技能、项目和成长可以共享这一结构，但需要使用各自的认证、排序和履约规则。

### 3.3 价值置换方式

- 货币：出售、租赁、雇佣和付费服务；
- 物物：物品、空间或使用权互换；
- 时间：咨询、陪练和技术支持互换；
- 能力：设计换开发、运营换摄影；
- 合作：工资、项目收益、共同成果或股权；
- 善意：赠予、志愿帮助、引荐和经验分享；
- 关系：不进行交易，只在双方自主意愿下建立连接。

首版不发行内部货币或 Token。

## 4. 核心体验：一树、一灵、一桥、一约、一程

| 产品对象 | 用户感知 | 核心作用 |
|---|---|---|
| 一棵生命树 | 我的资源、需要与成长全景 | 持续维护个人价值图谱 |
| 一个小天 | 真正站在我这一边的 AI 伙伴 | 理解意图、寻找连接、准备行动 |
| 一座桥 | 一次对双方都有价值的连接 | 展示双方收益、证据、冲突和未知项 |
| 一份桥约 | 双方愿意开始的行动约定 | 明确交换内容、第一步和完成方式 |
| 一段人生旅程 | 行动带来的真实变化 | 把结果写回生命树，形成成长记录 |

### 4.1 小天不是普通聊天助手

小天负责：

- 通过对话整理用户拥有和需要的价值；
- 将自然语言转成 Value Node 与 Intent；
- 追问真正影响连接的信息；
- 在授权范围内发现候选并与另一端小天交换必要摘要；
- 生成 Match Proof、桥约草稿和成长复盘。

不同灵宠外观只改变陪伴感，不改变能力。灵宠成长来自现实行动，而不是签到和刷信息流。

### 4.2 一座桥必须回答

- 你为什么需要对方；
- 对方为什么可能需要你；
- 哪些条件已经满足；
- 哪些信息仍未确定；
- 双方各自需要披露什么；
- 现在可以开始的最小行动是什么。

系统不使用无法解释的“98% 灵魂匹配”，而使用 `Match Proof` 展示可核对的理由。

### 4.3 桥约把连接变成行动

双方同意后，小天共同形成桥约：双方提供与获得什么、时间地点、费用或回报、第一次行动、完成标准和退出方式。

普通互助可以直接形成行动卡；房屋、雇佣、股权等高风险事项只形成意向，后续交给专业合同、支付和服务平台。

### 4.4 用户主流程

```text
表达拥有与需要
→ 小天生成节点和 Intent
→ 用户确认边界
→ 系统发现双向候选
→ 双方分别确认
→ 生成桥约与第一步
→ 结果写回生命树
```

首页围绕当前愿望、少量候选桥、待确认事项和下一步行动组织，不做无限信息流。

## 5. AI 原生性与创新

### 5.1 AI 从工具变成用户的代表

传统平台要求用户自己搜索、筛选、比较和私聊。天使桥让用户先表达完整意图，由小天持续理解、发现、澄清和准备行动。

### 5.2 从单边推荐变成 Agent-to-Agent 协商

两个小天先比较双方允许披露的结构化摘要，判断硬条件、双向收益和待确认问题，再分别向各自用户提出建议。关键决定始终由人完成。

### 5.3 从单类别标签变成跨类别价值翻译

AI 可以理解：

- 空间使用权可以交换摄影服务；
- 产品能力可以连接技术合作机会；
- 摄影教学可以交换英语陪练；
- 一个创意需要的不只是开发技能，还包括投入方式和长期目标。

### 5.4 从黑箱得分变成价值证明

系统展示双方各自获得什么、事实依据、冲突、未知条件和建议行动。LLM 负责理解与表达，代码负责结构、硬条件和状态。

### 5.5 从推荐结果变成成长闭环

产品不以“看到了一个候选”为完成，而以双方确认桥约并开始行动为完成。行动结果继续更新生命树，成为下一次连接的上下文。

## 6. 匹配、信任与边界

### 6.1 匹配流程

```text
领域识别
→ 时间、地点、资格等硬条件 Gate
→ A.need 搜索 B.offer
→ A.offer 搜索 B.need
→ 判断双方收益与证据
→ 生成 Match Proof
→ 双方分别确认
```

付费金额不进入自然匹配相关性。不同领域使用不同规则，不建立统一人生信用分。

### 6.2 渐进披露

- 私有：只供自己的小天整理；
- 匹配：以必要摘要参与候选发现；
- 双方确认后：开放进一步联系所需信息。

小天可以搜索、推荐和草拟，但不能替用户接受高风险连接。

### 6.3 关系与高风险场景

关系、健康、财产、工作等信息不得跨领域用于排序。房屋、招聘、投资和婚恋等场景需要各自的认证与合规机制；这些不在黑客松 MVP 中实现。

## 7. 产品差异与价值

| 产品类型 | 主要优化目标 | 天使桥的不同 |
|---|---|---|
| 内容社区 | 停留、互动和传播 | 围绕明确愿望与现实行动，不建无限流 |
| 电商与闲置 | 商品成交与 GMV | 支持跨类型、非货币的价值置换 |
| 招聘平台 | 岗位和简历转化 | 同时理解能力、项目、投入、回报和目标 |
| 社交与关系 | 浏览、喜欢和私聊 | 双向意愿、渐进披露和连接边界 |
| 通用 AI 助手 | 完成单次问答或任务 | 持续维护个人价值图谱并连接另一端意图 |
| 天使桥 | 现实价值流动与成长 | Agent 驱动表达、发现、协商、桥约和结果闭环 |

天使桥真正的竞争力不是覆盖多少类别，而是不同类别能否共享 Value Node、Intent、Match Proof、Consent 与 Bridge Pact。

## 8. 商业与增长逻辑

### 8.1 北极星指标

> **有效成桥数：双方确认桥约并开始第一次现实行动的连接数量。**

辅助指标包括节点确认率、双向价值清晰度、双方确认率、桥约启动率和行动完成率。产品不以停留时长和浏览量作为核心指标。

### 8.2 商业模式方向

- **个人免费层：** 基础生命树、少量活跃 Intent 和基础搭桥；
- **个人 Pro：** 更多愿望、更高扫描频率、更多外部来源和更深复盘；
- **商家与组织：** 认证资源节点、结构化询盘、社区价值网络和管理工具；
- **专业服务：** 将达成意向的房屋、雇佣或交易转交专业服务并收取技术服务费。

商业化不得绕过认证、隐私和双向意愿，也不得通过付费改变婚恋、招聘或公共资源的自然相关性排序。

### 8.3 发展路径

1. **0–1：** 在小型、高密度社区证明统一成桥机制；
2. **1–10：** 建立社区内部的技能、空间、项目和互助网络；
3. **10–100：** 接入垂直供给、地图、日历和专业履约服务；
4. **100–1000：** 开放 Value Node、Intent、Match Proof 和 Bridge Pact 协议，让外部 Agent 参与发现与协商。

## 9. 技术方向与黑客松边界

### 9.1 技术方向

```text
Next.js Web/PWA
→ 小天 Orchestrator
→ 结构化抽取与 Value Graph
→ 双向召回 + Domain Gate
→ Match Proof
→ 双方 Consent
→ Bridge Pact 与 Outcome
```

- 前端：Next.js、TypeScript、Tailwind CSS、shadcn/ui；
- 后端：Next.js Route Handlers；
- 数据：Supabase PostgreSQL、pgvector、Realtime；
- AI：OpenAI-compatible 中文模型、Zod 结构化输出；
- 部署：Vercel + Supabase。

首版只使用一个编排式 Agent，不为展示概念拆分自治 Agent 集群。

### 9.2 黑客松产品形态

选择移动端优先的 Web/PWA，不开发原生 APP。同一链接支持手机扫码、电脑投屏和快速部署，把时间集中在结构化理解、双向匹配、双方确认和桥约闭环。

### 9.3 数据边界

黑客松阶段不接入真实用户档案、房源、招聘、婚恋、交易或社区内容。所有人物、Value Node、Intent 和结果均为合成数据，并在界面和讲解中明确标注。

页面、接口、团队分工、96 小时排期和详细验收标准不在本文重复，统一见 [黑客松 MVP PRD](天使桥_黑客松MVP_PRD.md)。

## 10. Demo 证明

### 主案例：空间 × 服务

- A 有周末闲置工作室，需要品牌照片；
- B 需要两天拍摄场地，可以提供品牌摄影；
- 系统解释双方收益、证据与未知项；
- A/B 分别同意后，生成“两天空间使用权换一组品牌照片”的桥约；
- 完成后，连接结果写回双方生命树。

### 两个扩展案例

- 能力 × 机会：产品运营能力连接技术合作机会；
- 志趣 × 成长：摄影教学交换英语陪练。

主案例完整演示，另外两个案例只证明同一 Schema、API、匹配流程和桥约组件可以复用。

## 11. 参赛提交文案

### 作品名称

**天使桥 AngelBridge**

### Slogan

**让每一份价值，遇见真正需要它的人。**

### 作品描述

天使桥是一款 AI 原生的人生价值置换与资源连接系统。每个用户拥有一个专属 AI 伙伴“小天”，通过对话将物品、空间、能力、服务、机会和成长目标整理为由本人控制的人生价值图谱。当用户表达“我拥有什么、需要什么、愿意如何交换”时，系统通过统一 Intent、双向召回、领域约束和 Agent-to-Agent 协商，寻找双方都能获益的价值置换、资源交换或互助连接，并用 Match Proof 解释证据、冲突和未知条件。双方同意后，小天生成可执行的桥约，行动结果再回到生命树。天使桥不以流量和停留时长为目标，而以价值是否流动、连接是否推动愿望成为现实为目标。

### 路演收束

> **世界上不缺资源，也不缺愿望；缺的是一种让每个人被真正理解，让价值置换、资源交换与人与人的连接自然发生的共同语言。**
