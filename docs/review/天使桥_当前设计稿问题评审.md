# 天使桥｜当前设计稿问题评审

> 版本：v2.0（精简评审版）  
> 日期：2026-08-26  
> 文档性质：现状评审，不定义 MVP、页面范围或开发排期  
> 评审依据：[Idea 打磨与产品方案](../product/天使桥_Idea打磨与产品方案.md)｜[黑客松 MVP PRD](../product/天使桥_黑客松MVP_PRD.md)
> 评审对象：发现页、灵宠交互、语音输入和智能匹配结果等当前设计

---

## 一、总体结论

当前设计已经表达了三个有价值的方向：

- 用户可以用自然语言向小天表达复杂需求；
- 小天具有清晰、亲切的品牌形象；
- 产品尝试在同一入口连接人、物、空间和服务。

但如果不配合口头解释，评委更容易把它理解为：

> **小红书式信息流 + AI 语音助手 + 自然语言搜索。**

天使桥真正独特的部分——个人价值图谱、价值置换、双向资源连接、Agent 代表双方、Match Proof、桥约和成长闭环——还没有成为界面主角。

最核心的矛盾是：

> **团队在讲一套新的 Agent 价值网络，却仍使用信息流、热度、单向推荐和私聊等传统产品结构承载它。**

## 二、关键问题

| 优先级 | 当前设计问题 | 为什么影响产品成立 | 应遵循的设计方向 |
|---|---|---|---|
| P0 | 首页仍以双列信息流和频道为核心 | 产品会被理解为 AI 版小红书，继续依赖浏览和流量分发 | 首页围绕当前愿望、少量候选桥、待确认事项和下一步行动 |
| P0 | 匹配仍是“我提出需求，系统给我结果” | 只证明自然语言搜索，没有证明另一方为何愿意参与 | 每个结果同时展示双方分别获得什么 |
| P0 | 推荐停在内容卡片或私聊 | 产品价值终点仍是“看见了”，没有推动现实行动 | 双方独立确认后生成桥约和第一次行动 |
| P0 | “98% 匹配度”无法解释 | 形成虚假精确感，掩盖冲突、未知项和事实来源 | 使用 Match Proof 展示证据、冲突、未知项和建议 |
| P0 | 小天更像悬浮语音助手 | Agent-to-Agent 的核心创新无法被看到 | 让小天贯穿理解、发现、建议、确认、桥约和复盘 |
| P1 | 生命树没有进入主流程 | “人生价值图谱”和“成长”停留在品牌概念 | 节点由对话产生，行动结果必须写回生命树 |
| P1 | 类目很多但缺少统一结构 | 看起来像综合分类信息平台，而非同一价值模型 | 所有类别共享 Value Node、Intent、Match Proof 和 Bridge Pact |
| P1 | 灵宠、热度和内容视觉抢占注意力 | 产品容易被误判为 AI 宠物或娱乐社区 | 灵宠服务于反馈与陪伴，价值置换和资源连接保持最高层级 |

## 三、核心问题说明

### 3.1 首页不应继续复制流量平台

当前“推荐、找人、找物、资源、闲置、经验、视频、热门”等频道，加上双列卡片、点赞量和关注关系，仍要求用户浏览大量内容并自己筛选。

这与天使桥“摆脱流量逻辑”的主张直接冲突。用户来到这里不是为了看更多，而是为了推进一个明确愿望。

首页应优先回答：

- 我当前最重要的愿望是什么；
- 小天发现了哪几座值得看的桥；
- 哪些连接正在等待我确认；
- 今天可以完成的最小行动是什么。

### 3.2 资源交换必须是双向的

当前租房示例主要围绕位置、预算、户型和中介条件推荐房源。这可以证明 AI 理解搜索条件，但不能证明价值置换或资源交换。

一座真正的桥必须同时回答：

```text
你需要的  ←  对方能提供的
你能提供  →  对方需要的
```

如果另一方的需要、边界和确认没有进入流程，产品仍然只是更自然的搜索工具。

### 3.3 Match Proof 应替代黑箱百分比

“匹配度 98%”没有说明样本、算法、证据和计算方式，也没有告诉用户剩余 2% 是什么风险。

匹配详情应改为：

- 双方各自得到什么；
- 哪些硬条件已满足；
- 依据哪些合成事实；
- 存在哪些冲突；
- 哪些信息仍待确认；
- 小天建议的第一步。

这样才能让 AI 的判断可以被理解和核对。

### 3.4 产品不能停在推荐结果

当前流程在推荐卡、收藏或私信附近结束，而“桥”应当是双方同意后形成的行动关系。

完整产品逻辑是：

```text
表达 → 结构化 → 双向发现 → A 确认 → B 确认
→ 桥约 → 第一次行动 → 结果写回生命树
```

没有 Consent、Bridge Pact 和 Outcome，天使桥无法证明自己与推荐平台的区别。

### 3.5 小天需要成为流程主体

小天目前主要承担语音入口、陪伴浏览和回答问题，能力容易被理解为“悬浮聊天助手”。

小天应在每个关键环节承担清晰职责：

- 理解用户的拥有和需要；
- 提议 Value Node 与 Intent；
- 解释候选为什么双向有益；
- 代表自己的用户准备问题和桥约；
- 在关键动作前让主人确认；
- 行动后帮助复盘并更新生命树。

灵宠形象可以保留，但它必须是个人 Agent 的可视化形象，而不是产品的主要功能。

### 3.6 生命树必须由行动驱动

如果生命树只出现在个人主页或概念图中，它会成为装饰。它需要与主流程产生真实因果：

- 对话产生新节点；
- 用户确认节点和可见范围；
- Intent 从节点中生成；
- 桥约完成后形成新的花、果实或成长记录。

这样生命树才是个人价值图谱，而不是游戏化皮肤。

### 3.7 统一模型应比类目更突出

“找人、找物、租房、经验、视频”等栏目会让用户认为产品拥有多套互不相关的功能。真正需要被看见的是它们背后的共同结构：

- 我能提供什么；
- 我需要什么；
- 愿意如何交换；
- 有哪些条件和边界；
- 为什么双方值得连接；
- 下一步做什么。

类目用于领域规则和展示，不应成为产品第一层心智。

### 3.8 信任信息要简洁但明确

设计稿中的房源、人物和推荐结果缺少来源、时间、验证状态和模拟数据说明。黑客松阶段不需要建立完整认证体系，但必须诚实表达：

- 当前全部为合成人物和模拟资源；
- 哪些信息是预置设定；
- 哪些条件尚未确认；
- 高风险场景只形成模拟意向，不代表真实交易。

这不是增加复杂防御，而是避免评委误解产品已经使用真实资源或取得真实结果。

## 四、当前设计应保留的部分

### 4.1 自然语言表达

用户直接说出位置、预算、时间和交换偏好，比逐项填写筛选器更符合 AI 原生交互，应继续作为主要入口。

### 4.2 小天的品牌识别

灵宠把抽象 Agent 变成容易理解和建立关系的伙伴，是重要品牌资产。需要调整的是能力位置，不是删除形象。

### 4.3 语音入口

语音适合移动端和复杂表达，可以作为文字输入之外的增强能力，但不应成为产品创新的主要证明。

### 4.4 跨类别资源意识

当前设计已经尝试同时呈现人、物、空间和服务。下一步不是继续增加频道，而是让它们共享统一价值结构。

### 4.5 匹配过程反馈

搜索或匹配过程的动态反馈有助于表现小天正在工作。文案应说明“正在理解约束、寻找双向价值、检查未知条件”，而不是空泛地表示 AI 正在思考。

## 五、目标产品印象

| 当前容易形成的印象 | 应形成的印象 |
|---|---|
| AI 版小红书或分类信息平台 | AI 原生的价值置换与资源连接系统 |
| 小天帮助用户搜索内容 | 小天代表用户持续理解、发现和准备连接 |
| 匹配就是一个高百分比 | 匹配由双方收益、证据和未知项共同构成 |
| 推荐后进入收藏或私聊 | 双方确认后生成桥约并开始行动 |
| 生命树是个人主页装饰 | 生命树是被现实行动持续更新的价值图谱 |
| 灵宠是主要产品卖点 | 灵宠是个人 Agent 的情感化载体 |

---

## 六、评审结论

当前设计需要改变的不是配色或局部组件，而是产品中心：

> **从“让用户浏览更多推荐”，转向“让小天围绕明确愿望，促成一段双方都愿意开始的价值连接”。**

自然语言、语音、灵宠和跨类别内容都可以保留，但必须服务于同一条主线：

```text
理解个人价值
→ 发现双向连接
→ 双方确认
→ 形成桥约
→ 推动现实行动
→ 记录成长
```
